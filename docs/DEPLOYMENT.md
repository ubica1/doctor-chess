# Развёртывание на VPS

Нужны Linux VPS с Docker Engine и Compose v2, свободные TCP-порты 80/443 и домен с DNS A-записью на IP VPS. Если есть AAAA-запись, она тоже должна вести на этот сервер. Внешний доступ к 4173 не нужен: приложение доступно только Caddy в сети Compose.

## Первый запуск

После установки Docker по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/):

```sh
git clone https://github.com/ubica1/doctor-chess.git
cd doctor-chess
cp .env.example .env
```

В `.env` замените `chess.example.com` на свой домен без протокола, пути и порта. Затем:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 app caddy
```

Caddy получает и продлевает HTTPS-сертификат, перенаправляет HTTP на HTTPS. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https). При занятом 80/443 сначала согласуйте подключение к существующему reverse proxy; этот Compose предназначен для сервера со свободными портами.

Контейнер приложения содержит Python и Node.js и работает от непривилегированного пользователя. `DOCTOR_CHESS_HOST=0.0.0.0` открывает порт внутри контейнера. `DOCTOR_CHESS_PUBLIC_ORIGIN=https://<домен>` задаёт допустимый Origin и включает Secure для cookie. При обычном локальном запуске сохраняется привязка к 127.0.0.1. `/healthz` проверяет доступность приложения и соединения с БД.

## Данные и обновление

SQLite хранится в томе `chess-data` по `/data/chess.sqlite3`. Сертификаты хранятся в отдельных томах Caddy. Пересоздание контейнера сохраняет тома. [Документация Docker](https://docs.docker.com/engine/storage/volumes/).

Запускайте одну копию приложения: общий lock и очередь рассчитаны на один процесс. Изначально база сайта пустая; локальные аккаунты автоматически не переносятся.

Перед обновлением создайте согласованную копию БД через SQLite backup API и скачайте её с VPS:

```sh
docker compose exec -T app python -c "import sqlite3; src=sqlite3.connect('/data/chess.sqlite3'); dst=sqlite3.connect('/data/backup.sqlite3'); src.backup(dst); dst.close(); src.close()"
docker compose cp app:/data/backup.sqlite3 ./doctor-chess-backup.sqlite3
git pull --ff-only
docker compose up -d --build
```

Копия содержит приватные аккаунты и сессии; храните её вне репозитория и отдельно от VPS. Перед обновлением сохраняйте отдельную датированную копию. Не используйте `docker compose down -v`: это удаляет тома с данными.

Для переноса локальной базы сначала остановите локальный сервер, сделайте резервную копию всей папки `data`, затем согласуйте отдельный перенос. Не заменяйте базу уже работающего сайта.

## Проверка после запуска

Откройте `https://<домен>/healthz` — ожидается `{"ok":true}`. Проверьте регистрацию, вход и партию между двумя браузерами. Перезапустите контейнер и убедитесь, что профиль и партия сохранились. Для публичного сайта дополнительно настройте резервное копирование вне VPS и наблюдение за диском/нагрузкой. Встроенный HTTP-сервер и общая блокировка подходят для небольшого клуба; при росте нагрузки потребуется отдельная работа над серверной архитектурой.
